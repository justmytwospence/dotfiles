# What is worth sharing

Calibrated on what I archive in Inoreader. It is mostly practitioner essays on working with AI agents, writing about statistics and forecasting, and science and endurance pieces, read alongside a lot of news I never write about.

Raise an idea only if it would make a piece I would archive myself. That means it has at least one of these:

- **A claim someone could disagree with.** Write it as one sentence that stands on its own: "Writing is no longer proof of work." "AI safety is a systems-engineering problem, not a rogue-agent problem." "Approval buttons make oversight easy and understanding hard."
- **A measurement that explains something.** "I timed it: one output token costs 29x an input token, which is why pricing looks the way it does." It has to be a number this session actually produced, not a recap of the docs.
- **A named pattern that travels.** The session made something visible that has no good name yet ("PhDishing", "factory mode", "prompt cards"), and people who have never used my setup would recognize it in their own work.
- **A reversal from experience.** I believed X, this session showed Y, and it cost something real (time, money, data, trust).

It also has to:

- **Generalize.** It must matter to someone who uses none of my tools. The lesson is the subject, and the tool is only the example.
- **Rest on what happened in this session.** No speculation, no generic best practice.

Never raise:

- How I wired X to Y, configured a tool, migrated a setup, or fixed a bug. That is plumbing, however clever. It passes only if it shows a general claim above, and then the claim is the idea.
- Release notes, feature announcements, "TIL the API has an endpoint for this".
- Anything only my homelab, my dotfiles or this codebase would care about.
- Anything confidential: credentials, private names, client or employer details, hostnames, paths.

When unsure, do not raise it. One great idea a month beats one mediocre idea a day.

## The short post

One idea, in first person, in plain words. Start with the claim or the number, not "TIL" or "I built". End on the implication or an honest open question. No hashtags, no emojis, no thread bait. A link only if it is where the evidence lives.
